# ADR-0002. 完成落地航向互校后才能自动判定可交付

## 状态

Accepted。业务规则已确认。「未互校即判不可交付」的判定差距尚未修复；
「转圈互校从未执行」的实现缺陷已于 2026-11-07 修复，待实车验收。

## 实现记录

- **2026-11-13 判据拆分：打滑率不再否掉互校通过。** 实测姿态误差
  0.42~0.96°（容差 3°）、IMU 累积 ±360.8~361.0°，车确实转满了，
  但打滑率 45~52% 超出理论值容差 → 判 WARN → 连带 IMU/里程计保持 PENDING。
  现改为：**姿态误差是唯一决定 `verified` 的指标**，打滑率降为独立 WARN。
  见 [ADR-0008](0008-spin-verified-criteria.md)。
- **2026-11-07 修复：转圈互校一次也没跑过。**
  `_run_ground` 把 `motion.ground` 段当成整个 `motion` 传给了 `_run_spin`，
  而 `_run_spin` 读的是 `cfg["spin"]`，于是每一台车都落入
  「配置缺失，未执行」分支。实车 2026-11-07 20:06 的报告即为此状态：
  落地段有前进/后退/左右转向，却没有任何一行转圈数据，第 18 项被判 SKIP。
  改为 `ground` 与 `spin` 两段分别传参；新增回归测试，断言
  `_run_ground` 必须调用两次 `spin_probe`，以及缺少 `spin` 段时退化为 SKIP
  而不是报错。
- 同时修正判定文案：SKIP（有项没验证完）不再被写成「存在失败项」。
- **仍待完成（两个不同的缺口，不要混淆）**：
  1. **未互校时的自动不可交付判定**（本文决策要求的核心）。
     `motion_level == "none"` 时 IMU 与里程计仍可能保留 PASS，
     整机可能显示「可交付，但需确认」—— 尚未满足决策。
  2. **转圈的实车验收**。代码路径已修好并有单元回放，
     但需要在开阔平地真实跑左右各一圈才能确认判定阈值合理。

## 背景

IMU 与里程计的静态频率和漂移正常，不代表车辆行驶时的航向精度已验证。用户已确认：没有完成落地航向互校时，自动交付结论应为不可交付。

当前 `motion_level == "none"` 时，这两项可能保留 PASS 并只在摘要提示未验证；第 18 项为 SKIP 时，整机可能显示「可交付，但需确认」。`Report.verdict` 已对致命项 PENDING 判不可交付，但不能覆盖上述状态未进入 PENDING 的场景。

## 决策

- 未完成落地航向互校时，自动判定不可交付；包括未选择运动、只做架空运动或互校未完成。架空检测通过但互校未完成的 IMU、里程计保留 PENDING；明确失败或没有必要数据时保留相应状态及原因。
- 自动结论与人工复核分开保存和展示；人工接受不能覆盖原始结果或自动判定。例外放行是否允许及审批权限仍需确定。
- 图形界面和报告使用一致的自动判定。原 Python CLI 已移除，退出码要求不再适用。
- 运动过程保留电压检查、人工确认、取消、停车和 ROS 清理，不能通过绕过安全条件完成验证。

## 替代方案

- 未互校时只按未验证比例判断：少量缺项可能落在容忍比例内，无法保证航向验证完成。
- 人工勾选后直接改写自动结论：会掩盖实际未完成的验证及责任边界。

## 影响

场地不允许落地运动时自动结论保持不可交付。实现时需覆盖未选运动、架空、互校未完成和失败等分支，并检查图形界面和报告；自动化替身结果不代表实车验收。
