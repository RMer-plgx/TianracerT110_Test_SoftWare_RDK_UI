# ADR-0002. 完成落地航向互校后才能自动判定可交付

## 状态

Accepted。业务规则已确认，当前实现存在差距，尚未完成修复或实车验收。

## 背景

IMU 与里程计的静态频率和漂移正常，不代表车辆行驶时的航向精度已验证。用户已确认：没有完成落地航向互校时，自动交付结论应为不可交付。

当前 `motion_level == "none"` 时，这两项可能保留 PASS 并只在摘要提示未验证；第 18 项为 SKIP 时，整机可能显示「可交付，但需确认」。`Report.verdict` 已对致命项 PENDING 判不可交付，但不能覆盖上述状态未进入 PENDING 的场景。CLI 对 FAIL 返回 1，对中止或未验证比例超过 20% 返回 2，其他情况返回 0，致命项 PENDING 等不可交付情况可能返回 0。

## 决策

- 未完成落地航向互校时，自动判定不可交付；包括未选择运动、只做架空运动或互校未完成。架空检测通过但互校未完成的 IMU、里程计保留 PENDING；明确失败或没有必要数据时保留相应状态及原因。
- 自动结论与人工复核分开保存和展示；人工接受不能覆盖原始结果或自动判定。例外放行是否允许及审批权限仍需确定。
- GUI 和 CLI 使用一致的自动判定。CLI 在自动不可交付或无法判定时不得返回 0，并区分失败与未完成；「可交付，但需确认」的退出码和脚本兼容方案待确定。
- 运动过程保留电压检查、人工确认、取消、停车和 ROS 清理，不能通过绕过安全条件完成验证。

## 替代方案

- 未互校时只按未验证比例判断：少量缺项可能落在容忍比例内，无法保证航向验证完成。
- 人工勾选后直接改写自动结论：会掩盖实际未完成的验证及责任边界。

## 影响

场地不允许落地运动时自动结论保持不可交付。实现时需覆盖未选运动、架空、互校未完成和失败等分支，并检查两个入口、退出码与报告；自动化替身结果不代表实车验收。
