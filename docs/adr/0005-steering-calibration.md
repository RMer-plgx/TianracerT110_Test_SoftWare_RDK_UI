# ADR-0005. 转向角只能间接测量，标定后才谈得上互校

## 状态

Accepted（2026-11-10）。首次标定完成，且**判据已按物理约束重写**。
只覆盖 14°~20° 区间；更高角度、更高速度以及换车后的复现都未验证。

## 背景

第 18 项的「落地航向互校」原本只比较 IMU 与 odom 的航向差。这个指标有一个
盲区：**它比的是两个航向传感器，不比转向角。**

如果舵机卡在中位，车根本不转，IMU 和 odom 都是 0，差值也是 0 —— 反而判 PASS。
换句话说，原来的互校能发现「轮子转了车没转」（打滑），
**发现不了「转向执行没跟上指令」**。

要真正验证转向，就需要知道舵机实际转了多少。而这台车**读不到**：

```
协议下行帧只有四类：ODOM_RESPONSE / IMU_REPONSE / Voltage_RESPONSE / DEBUG_RESPONSE
没有任何一个携带转向角
```

改 MCU 固件加回传不在当前授权与能力范围内。

## 决策

在无法直接测量舵机角的前提下，采用**间接测量 + 一次性标定 + 常量修正**：

1. 用恒定转角跑稳态圆弧，从 IMU 实测角速度反推真实转角：
   `ω = θ_imu / T`，`R = v_real / ω`，`δ_real = atan(L / R)`
2. `v_real` 不能直接用指令速度 —— 打滑会让轮速高估。用
   `s = (|θ_odom| − |θ_imu|) / |θ_imu|`、`v_real = v_cmd / (1 + s)` 修正
3. 三路独立算法交叉验证（指令速度 / 打滑修正 / 弦长），偏差大则说明假设失效
4. 标定结果以 `steer_gain` / `steer_offset_deg` 写入 baseline，
   并用于把指令角换算成真实角

标定结果**不参与自动判定**，只作为报告里的测量项公布。等积累足够样本、
确认打滑修正稳定后，再考虑是否计入。

## 标定结果（2026-11-10）

轴距 0.255 m（卷尺实测），速度 0.12 m/s，单组 8~10 秒稳态圆弧，6 组有效数据。

```
δ_real = 0.910 · δ_cmd + 0.58°        残差 RMS 0.15°，最大 0.28°
```

| 指令 | 实际 | 比例 |
| --- | --- | --- |
| 14.32° | 13.74° | 0.959 |
| 17.19° | 15.94~16.28° | 0.927~0.947 |
| 20.05° | 18.79~19.00° | 0.937~0.948 |

左右对称性 0.2~0.3°，打滑率 26%~45%。

**0.35 rad（20.05°）指令，实际约 18.8°。** 这与「按名义 20.05° 算几何」
差 1.2°，对应半径从 0.699 m 变成 0.749 m —— 空间规划时按哪个算会差 7%。

三路交叉校验（0.35 左转）：若打滑均匀，
`R_C 应 ≈ R_B × (1+s) = 0.956`，实测 `0.879`，偏差 8%。
吻合度说明「打滑均匀」这个一阶假设成立，`δ_B` 是三者中最可信的。

## 替代方案

- **只比 IMU 与 odom**：能测打滑，测不出舵机偏差。已在用，但要认清边界。
- **人工拿量角器量**：只能静态抽查，无法反映负载下的实际转角。
- **改 MCU 固件加角度回传**：最彻底，但需要固件源码与烧写授权，当前不具备。
- **装外置角度传感器**：精度最高，需要加硬件、改线束。

## 影响

- `HARD_MAX_STEER = 0.5`（28.6°）是 2026-11-03 实现时随手定的保守上限，
  **不是厂家规格、不是实测**。本轮标定只验证到 0.35 rad，
  0.5 作为不可超越的硬顶保留，但没有任何数据支撑它对应真实物理限位。
  要确定真实限位，需要单独做「逐步加大转角直到车轮不再响应」的实验，
  风险较高，未做。
- 标定系数绑定**这台车、这个舵机、这个速度**。换车、换舵机、改悬挂后必须重测。
- 打滑率 26%~45% 说明 T110 在 0.12 m/s + 大转角时轮胎打滑严重。
  这既是 `spin` 闭合误差大的原因，也限制了间接测量的精度。
- `steer_gain` 用于把指令角换算成真实角，但**不改变下发的指令** ——
  检测工具不应该替底盘做闭环。若要让真实转角达到 20.05°，
  应按 `(20.05 − 0.58) / 0.910 = 21.4°` 下发，这属于底盘标定范畴，不在检测工具内做。

## 未验证

- 0.20 rad 以下（本次因场地不足未测）
- 0.35 rad 以上（未测，且无安全场地）
- 速度变化对标定的影响（本次固定 0.12 m/s）
- 负载/地面材质变化的影响
- 长时间使用后舵机中位漂移
- **3° 姿态容差在小样本下的稳定性** —— 只有两次样本（1.11° / 0.75°）


## 追加发现（2026-11-10）：打滑是几何必然，不是故障

决定性的一次实验：用 IMU 闭环转满 360°，测能否回到原地。

| | 左转 | 右转 |
| --- | --- | --- |
| IMU 累积 | 360.68° | −361.04° |
| odom 累积 | 463.28° | −485.64° |
| 打滑率 | 28.4% | 34.5% |
| **闭合误差** | **1.1188 m** | **1.274 m** |
| 耗时 | 49.82 s | 53.03 s |

**IMU 闭环本身是准的**（过冲 0.68° / 1.04°），但车回不到原点，差 1.1~1.3 米。

### 为什么必然打滑

T110 是**阿克曼四驱**：一个电机经齿轮/皮带带四个轮子，**四轮转速强制相同**。

从 URDF（`tianracer_compact.urdf`）取到的几何：

```
轴距 L = 0.261 m   轮距 W = 0.163 m
```

三个结构性矛盾叠加：

1. **内外轮速需求不同**：`W/R`。δ=0.35 时 R=0.715，需差 22.8%，
   但四驱只给同一转速。
2. **前后轴路径不同**：前轴走 `√(R²+L²)`，比后轴长 6.5%，同速必有一轴被拖。
3. **单舵机做不到真阿克曼**：理想内轮 22.4°、外轮 18.1°（差 4.3°），
   单舵机拉杆只能给一个角，近似平行转向，前轮额外侧滑。

理论合计 `22.8 + 6.5 = 29.3%`，实测左转 28.4%、右转 34.5%。
**左转几乎完全吻合**，说明打滑量由几何决定，与速度、路面关系不大。

### 由此推翻的旧判据

旧判据拿 `|IMU − odom|` 判 PASS/FAIL，容差 15°/30°。
而实测差值常年 100°+（必然打滑），**等于用一个物理上达不到的标准判它失败**。

新判据分三层：

| 项 | 判据 | 依据 |
| --- | --- | --- |
| **车体姿态** | `|IMU − target| ≤ 3°` | 唯一不受打滑污染的直接测量（详见下节） |
| **打滑率** | 与 `expected_slip()` 理论值比对，偏差 ≤ 15 个百分点 | **只告警，不决定互校是否通过**（2026-11-13 改，见 ADR-0008） |
| **闭合误差** | 只记录，不判定 | 无可靠解析估计（实测 1.12 m，而 R×打滑率只给 0.21 m，差 5 倍） |

`expected_slip(wheelbase, track, steer)` 见 `core/geometry.py`，
输出 `lateral_pct` / `fore_aft_pct` / `total_pct`，供判据直接使用。

### 打滑率不再否掉互校通过（2026-11-13）

实测两台次：姿态误差 0.42~0.96°（容差 3°）、IMU 累积 ±360.8~361.0°
（目标 ±360°）—— 车确实转满了一圈 —— 但打滑率 45~52%
（理论 30% ± 15，上限 45%）判 WARN，连带 IMU/里程计保持 PENDING。

打滑率主要反映**地面摩擦**（同一台车换块地能差 10pp 以上），
而姿态精度是车本身的能力。把两者绑在同一个 `verified`
里，等于让「今天铺的什么地」决定「这台车能不能交付」。

现在：姿态误差是唯一决定 `verified` 的指标；打滑率超标仍判 WARN，
作为「地面摩擦异常 / 可能某轮卡死」的独立提示。详见 [ADR-0008](0008-spin-verified-criteria.md)。

### 姿态容差从 15° 收紧到 3°（2026-11-10 晚）

初版把姿态容差定在 15°，那是当时**没有实测数据**时拍的保守值。
两次实车转圈之后有了依据：

| | 姿态误差 |
| --- | --- |
| 左转 | 1.11° |
| 右转 | 0.75° |

IMU 闭环本身很准（过冲 < 1.1°），15° 相当于把「差 4% 就能过」写在判据里，
抓不住「少转一截」这类真故障。故改为：

```yaml
motion.spin.yaw_tolerance_deg: 3    # 合格线
motion.spin.yaw_warn_deg: 8         # 告警线，必须比合格线宽
```

3° 是实测水平的 3~4 倍余量。**风险**：只有两次样本，统计上不够。
若在别的场地/温度下偶发 3~5° 的 FAIL，应先怀疑噪声而不是回退到 15° ——
判断方法是看同一台车重复跑，若结果在 3° 上下跳而车本身没异常，那就是噪声。

注意：`checks/motion.py` 里的 `15.0` 只是配置缺失时的兜底常量，
配置在就一定用配置值。改容差**不需要改代码**。

### 场地要求必须重算

之前按纯圆弧算 0.35 rad 需外环 0.913 m，**漏了打滑**。
实测转一圈漂移 1.1~1.3 m，实际需要：

```
半径 0.715 + 漂移 1.3 ≈ 2.0 m  →  4 米见方（保守 4.5 m）
```

这是 2026-11-10 两次撞车的深层原因：空间校验只算圆弧，没算滑移。
`probes/space_probe.py` 的扫掠判定仍未包含此项，后续应补 `slip_allowance`。

### 对「回到原地」这类需求

在四驱同速 + 单舵机 + 0.163 m 轮距的条件下，**回原地在物理上不可能**。
要让打滑降到 5% 以下需要 `R > W/0.05 = 3.26 m`，即转角 < 4.6°，
转一圈需 20 米直径的场地。现实中不可行。

因此任何要求「闭合误差接近 0」的测试流程都不适用于本车型。
若要减小漂移，只能改用交替转向（S 形）让左右漂移互相抵消，
但轨迹更复杂、占地更大，且只能减小而不能消除。
