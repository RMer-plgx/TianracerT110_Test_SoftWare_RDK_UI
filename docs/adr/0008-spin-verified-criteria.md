# ADR-0008. 落地互校的「通过」只由姿态误差决定，打滑率不参与

## 状态

Accepted（2026-11-13）。待实车验收。

## 背景

第 18 项的落地转圈会让 IMU 与里程计从 PENDING 转 PASS。转 PASS 的条件是
`_run_spin()` 返回 `verified=True`，而现在的实现是两层与门：

```python
# checks/motion.py:536-539
st = judge_max_only(abs(dev), slip_tol, slip_tol * 2)
statuses.append(st)
if st is not Status.PASS:
    verified_all = False

# checks/motion.py:594
return statuses, verified_all and all(s is Status.PASS for s in statuses)
```

也就是说：**姿态误差、打滑率、闭合误差（记录项外）、未转满一圈，
任何一项不是 PASS，整个互校都算未通过。**

### 实测暴露的问题

2026-11-13 在某台 T110 上连测两次（`dist/test records/192.168.1.165_*`）：

| | 11:11 | 11:25 | 容差 |
| --- | --- | --- | --- |
| 左转姿态误差 | 0.66° | 0.96° | ≤ 3° ✅ |
| 右转姿态误差 | 0.42° | 0.75° | ≤ 3° ✅ |
| 左转 IMU 累积 | — | +361.0° | ±360° ✅ |
| 右转 IMU 累积 | — | −360.8° | ±360° ✅ |
| 左转打滑率 | 45% | 46% | 理论 30% ± 15 ⚠️ |
| 右转打滑率 | 52% | 50% | 同上 ⚠️ |

**车转得很准**：姿态误差不到 1°（容差 3°），IMU 累积 361.0° / −360.8°
说明确实转满了一圈。但打滑率比理论值高 15~20 个百分点，判了 WARN，
于是 `verified=False`，IMU 与里程计保持 PENDING。

用户看到的现象是：「车明明画完圈了，为什么 IMU 还是待验证」。

## 决策

**`verified` 只由「车体姿态是否转够」决定。** 打滑率降为独立告警项。

| 指标 | 旧作用 | 新作用 |
| --- | --- | --- |
| 姿态误差 ≤ `yaw_tolerance_deg` | 决定 verified | **决定 verified**（不变） |
| 打滑率偏离理论 ≤ `slip_tolerance_pct` | 决定 verified | **只判 WARN，不决定 verified** |
| 闭合误差 | 只记录 | 只记录（不变） |
| 未转满一圈（`reached=False`） | 否掉 verified | 否掉 verified（不变） |
| 无 IMU 数据 | SKIP，否掉 verified | 不变 |

### 为什么

**打滑率主要反映地面摩擦，不是车的能力。**

- 同一台车，水泥地 / 环氧地坪 / 瓷砖上打滑率能差 10 个百分点以上
- 理论值 30% 来自 2026-11-10 某一次具体场地的标定
  （`baseline.yaml` 的 `motion.spin` 注释里写明了来源）
- 而 IMU 姿态精度是车本身的能力，与地面无关

把环境指标和功能指标绑进同一个 `verified`，等于让「今天铺的什么地」
决定「这台车能不能交付」。

### 打滑率仍然有意义

它不能被删掉，因为偏离理论值过多**可能**是真故障：

- 某轮卡死 → 打滑率异常升高
- 轮胎漏气 / 胎压不均
- 地面有油污

所以保留 WARN，并在报告里写清两者的关系：
「打滑率反映地面摩擦，不影响 IMU 姿态精度判定」。

## 替代方案

- **维持现状（打滑率也否 verified）**：换地面就红，用户会逐渐无视这一项。
  已失效一次，不接受。
- **删掉打滑率判定**：会漏掉「某轮卡死」这类真故障。不接受。
- **把打滑率容差放宽到 ±25pp**：治标。地面差异可能更大，而且放宽阈值
  会让真故障更难被抓到。不如把它从 `verified` 里摘出来。

## 影响

- 第 18 项的状态会更容易变成 PASS。**这是有意为之**：车真转准了就该过。
- 打滑率超标时，第 18 项仍是 WARN（因为 WARN 由 `judge_all(statuses)` 汇总），
  但 IMU/里程计会转 PASS。报告里能同时看到「第 18 项 WARN」和「IMU PASS」。
- 如果将来发现「打滑率超标 + 姿态达标」其实意味着某种真故障，
  应该新增一项独立检测，而不是回退到把两者绑在一起。

## 未验证

- **「打滑率 45~52% 只反映地面」这个结论的置信度是「中」**，
  因为只测了同一台车、同一块地、15 分钟内两次。没有换地面做对照。
- 建议在实施后累计 5~10 台车的数据，如果发现「姿态达标但打滑率异常高」
  总是对应真故障，需要重新审视本决策。
